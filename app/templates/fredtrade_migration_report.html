Kết Luận Nhanh

Khả thi: Tích hợp được Khuyến nghị: Dùng service riêng Rủi ro: Aster chưa official support trong Freqtrade
  • Freqtrade là framework/bot trading crypto mã nguồn mở bằng Python, mạnh ở engine giao dịch, backtesting, hyperopt, API/WebUI/Telegram.
  • Với BOktoshi, hướng phù hợp nhất là tích hợp kiểu sidecar/microservice; không nên nhúng sâu trực tiếp vào cùng process FastAPI hiện tại.
  • Aster có thể kết nối theo hướng kỹ thuật vì Freqtrade đi qua CCXT, và CCXT có adapter aster; tuy nhiên Freqtrade chưa xếp Aster vào danh sách exchange official support.
  • BOktoshi có thể kết nối Freqtrade qua REST/WebSocket để đồng bộ trạng thái, lệnh, trade history và health.
Khuyến nghị chốt: triển khai theo mô hình BOktoshi UI/API + Freqtrade Engine Service + Adapter Mapping để giữ UI hiện tại, đồng thời tận dụng full sức mạnh backtest/hyperopt/FreqAI.

Freqtrade Là Gì

  • Kiến trúc bot đầy đủ: load config, load exchange, load strategy, chạy vòng lặp stateful với worker loop.
  • Hệ strategy plugin + callback sâu, phù hợp mở rộng theo chiến lược tùy biến.
  • Tích hợp runtime production: REST API, message websocket, webhook, telegram, discord.
  • Có producer/consumer mode để tái sử dụng indicator/signals giữa nhiều instance.
  • Có persistence chuẩn bằng SQLite/SQLAlchemy và các mô-đun backtest/hyperopt/FreqAI.
Giá trị lớn nhất với BOktoshi: giảm thời gian tự xây engine giao dịch từ đầu, tập trung vào adapter, chiến lược và UX vận hành.

Đối Chiếu Với BOktoshi Hiện Tại

  • BOktoshi hiện có FastAPI app + bot loop riêng + client gọi API trực tiếp cho MTC/Hyperliquid/Aster.
  • Điểm mạnh: dashboard/manual/journal đã tách rõ, phù hợp để gắn external engine theo lớp adapter.
  • Điểm yếu: chưa có exchange abstraction thống nhất, bot runner còn phụ thuộc mạnh vào client cụ thể.
  • Hướng cải tiến: trừu tượng hóa tầng thực thi thành ExecutionBackend, sau đó thêm MTCBackend và FreqtradeBackend.
Điểm cần lưu ý: cần thống nhất format symbol, trade id, trạng thái vị thế, PnL để journal không lệch dữ liệu.

Tích Hợp Với BOktoshi: Tích Hợp Hay Làm Riêng

Khuyến nghị kiến trúc

  • Nên làm service riêng: chạy Freqtrade độc lập và BOktoshi gọi qua REST/WebSocket.
  • Không nên merge source sâu: Freqtrade có lifecycle/state machine/threading riêng, nhúng chung process sẽ khó debug và nâng cấp.
  • Bảo toàn hệ hiện tại: vẫn giữ manual control, dashboard, journal trong BOktoshi; chỉ thay hoặc bổ sung engine execution.

Rủi ro/chi phí chính

  • Phát sinh tầng mapping dữ liệu giữa 2 hệ.
  • Cần cơ chế đồng bộ trạng thái chạy/dừng/trade slot giữa BOktoshi và Freqtrade.
  • Cần kiểm thử kỹ các hành vi force enter/force exit để không sai lệch logic vận hành hiện tại.
  • Cần lưu ý ràng buộc license GPLv3 nếu copy/chỉnh sửa sâu code lõi Freqtrade.

Aster Và BOktoshi Có Kết Nối Được Không

  • Aster: khả thi theo đường CCXT; CCXT có adapter aster cho cả market và trading endpoints.
  • Freqtrade official support: hiện chưa liệt kê Aster trong danh sách exchange subclass chính thức.
  • Thực tế triển khai: có thể chạy dạng community/experimental, bắt buộc PoC + dry-run + kiểm thử lệnh thật trước khi live.
  • BOktoshi: kết nối tốt qua REST + WebSocket của Freqtrade để đưa dữ liệu lên dashboard và điều khiển lệnh.
Kết luận Aster: làm được, nhưng cần chiến lược rollout an toàn theo từng pha thay vì bật live ngay.

Roadmap Triển Khai Đề Xuất

  • Phase 1 (2-4 ngày): chạy Freqtrade riêng, BOktoshi chỉ đọc status/trades/balance/health.
  • Phase 2: bổ sung adapter mapping cho journal và chuẩn hóa trade schema.
  • Phase 3: migrate 1 strategy hiện tại sang strategy class của Freqtrade để backtest/hyperopt.
  • Phase 4: test Aster dry-run, đánh giá độ ổn định order/position mode rồi mới canary live.

Thiết Kế Tích Hợp Chi Tiết (Endpoint-by-Endpoint)

Mục tiêu: giữ nguyên contract phía UI/Frontend BOktoshi, thêm tầng adapter trong backend để nói chuyện với Freqtrade API.

Mô hình: Frontend -> app/main.py (Boktoshi API) -> FreqtradeAdapter -> Freqtrade REST/WebSocket

1) Mapping endpoint hiện tại sang Freqtrade

Endpoint BOktoshi Freqtrade API tương ứng Chiều mapping Ghi chú xử lý
GET /api/status GET /show_config, GET /health, GET /status Freqtrade -> BOktoshi Map state, strategy, số lệnh mở, health tick về payload status hiện có.
GET /api/account GET /balance, GET /profit Freqtrade -> BOktoshi Tổng hợp số dư stake + PnL để giữ nguyên block Account Overview.
GET /api/open-positions GET /status Freqtrade -> BOktoshi Map trade mở của Freqtrade sang schema position strategy/manual của BOktoshi.
GET /api/trade-history GET /trades?limit=&offset= Freqtrade -> BOktoshi Map fields: trade_id, pair, side, open_date, close_date, profit.
GET /api/pnl-history GET /daily, /weekly, /monthly Freqtrade -> BOktoshi Dùng daily làm mặc định cho chart, weekly/monthly cho tổng quan.
GET /api/logs GET /logs Freqtrade -> BOktoshi Chuẩn hóa level/timestamp để render log-list không cần đổi UI.
POST /api/strategy/select POST /reload_config hoặc switch bot instance/strategy config BOktoshi -> Freqtrade Freqtrade không có endpoint select strategy runtime trực tiếp; cần cơ chế config profile + reload.
POST /api/strategy/run-all N/A trực tiếp Adapter nội bộ Thiết kế nhiều bot instance theo từng strategy hoặc strategy đa cặp trong Freqtrade.
POST /api/manual/force-open-long POST /forceenter với side=long BOktoshi -> Freqtrade Map symbol, stakeamount, leverage, ordertype, entry_tag.
POST /api/manual/force-open-short POST /forceenter với side=short BOktoshi -> Freqtrade Yêu cầu mode futures và exchange hỗ trợ short.
POST /api/manual/close-position POST /forceexit BOktoshi -> Freqtrade Dùng tradeid đã map từ BOktoshi external_id.
POST /api/manual/close-all-positions POST /forceexit với tradeid=all BOktoshi -> Freqtrade Cần guard xác nhận thao tác nguy hiểm ở backend.
POST /api/manual/close-strategy-position POST /forceexit theo danh sách trade strategy-owned Adapter nội bộ Dựa vào entry_tag/strategy_id để lọc trade thuộc strategy.
POST /api/manual/close-all-strategy-positions POST /forceexit nhiều lần hoặc batch điều phối Adapter nội bộ Loop trade theo tag chiến lược, đóng tuần tự có retry.

Ghi chú: endpoint Freqtrade tiền tố /api/v1 trong runtime thực tế.

4) Bảo mật, vận hành, quan sát

  • Không mở Freqtrade API public internet; chỉ bind nội bộ hoặc qua VPN/SSH tunnel.
  • Dùng username/password mạnh + jwt_secret_key + ws_token ngẫu nhiên đủ dài.
  • Thiết lập timeout/retry/circuit breaker ở adapter để tránh treo dashboard khi Freqtrade chậm.
  • Thêm health check nền: nếu Freqtrade down, BOktoshi chuyển trạng thái "degraded" và khóa endpoint thao tác nguy hiểm.

5) Kế hoạch triển khai cho dev (ngắn gọn, làm ngay)

  • Tạo FreqtradeAdapter + mapper trước, chỉ tích hợp luồng read-only (status/account/history/logs).
  • Bật thao tác write sau: force-open-long/short, close-position, close-all với feature flag.
  • Giữ nguyên UI response contract để frontend không phải sửa lớn.
  • Canary 1 strategy + 1 symbol trước (ví dụ ETHUSDT), sau đó mở rộng BTC/SOL.
  • Chỉ chuyển live sau khi pass checklist dry-run + log reconciliation + PnL reconciliation.
Chốt triển khai: Tích hợp Freqtrade theo lớp adapter là hướng nhanh nhất, an toàn nhất và ít rủi ro nhất để nâng cấp BOktoshi lên mức production-grade trading engine.
